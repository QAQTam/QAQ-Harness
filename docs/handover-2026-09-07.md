## 六、方法论教训（给下一个执行者）

1. **子代理报告结论可信、数字需复核**。本次实测偏差：`push_tool_results_batch` 报 100 行实为 21 行（`push_tool_result_inner` 是活跃函数被误并入）；`handle_run` 报"被 bash/pwsh 共用"实为零调用死函数；`process_is_running` 报"语义相同"实为有意不同实现；`detect_os_info` 漏报了 TOOLS_INFO 侧影响。**所有删除前必须 rg 全量复核 + 读原文定边界**（本轮多次因此避免错误删除）。
2. **codegraph callers 有漏报先例**（上轮审计已警示），仅作探索加速，不作删除依据。
3. **跨 crate 的 `Err(String)` 通道动不得**（除非连带改 service.rs 错误面）——todo.rs 38 处因此收敛为 `json_err_string` 而非强行结构化。
4. **git checkout 恢复是整文件级**：Phase 1 执行中 `git checkout -- crates/qaqh-workspace/src/` 曾把已完成的 lib.rs json_err 改动一并回滚，需留意恢复范围。
5. **文本替换脚本必须跳过字符串字面量**做括号配对（message 里的引号会破坏深度计数）；Rust 的 `ToolResult::error(json_err(...))` 双层包裹解除用「前缀定位 + 内层配对 + 跳外层闭括号」三步法，首轮脚本两次踩坑。
6. 验证纪律：每批改动 `cargo check` → 相关 crate test → 阶段收口 `cargo test --workspace + clippy --all-targets + fmt --check` 三连；**删除类操作引发的新警告（如 unreachable pattern、never used）是连锁死代码的信号**，本轮由此多清了 `handle_run` 和一个 match 分支。
7. **对外可见面不动**红线继续有效：JSON wire shape、daemon.json 格式、bindings/qaqh TS 面、workspace CLI 词表、Ringing V1 协议。错误协议统一前已 grep bindings/ 确认 TS 侧零耦合。
